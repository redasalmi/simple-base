Guidelines

Component usage

Recommended

Default variants

Use for structured UI

Use default variants for forms, settings, tables, cards, and predictable application surfaces.

Command variants

Use for fast actions

Use command variants for search, command palettes, shortcut-driven menus, and launcher flows.

Muted variants

Use for low priority

Use muted variants for disabled controls, background metadata, readonly states, and archived content.

Accessibility

Interaction notes

A11y
  • Use native semantic elements when possible: button, input, select, details, table, nav.
  • Icon-only buttons must include an accessible label with aria-label or visible text.
  • Dialogs should include labelled titles and descriptions using aria-labelledby and aria-describedby.
  • Preserve visible focus states using lime or subtle ring tokens.
  • Do not rely on color alone for destructive, success, or active states.

Rules

Do and don’t

Design rules

Do

Preserve dark depth

Layer near-black surfaces, use compact spacing, keep text hierarchy muted, and reserve lime for important active states.

Don’t

Avoid visual noise

Don’t use large saturated backgrounds, broad gradients, pure white button fills, or many competing accent colors.
