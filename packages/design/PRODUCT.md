# Product

## Register

product

## Platform

web

## Users

Simple Base is built first for its creator, who uses it to build productivity applications such as invoicing, Pomodoro, and note-taking tools. It will also be public for developers building websites and applications who want a distinctive, adaptable design foundation.

The primary job is to assemble polished interfaces quickly without redesigning foundational components for every project. Public users should be able to adopt the system, select or customize a theme, and build confidently from consistent components and tokens.

## Product Purpose

Simple Base provides a reusable design foundation for visually appealing, professional software. It should make it fast to build polished productivity tools while remaining flexible enough for broader websites and applications.

Success means its creator can produce cohesive interfaces without repeatedly solving the same component-design problems, while external developers can understand, adopt, theme, and extend the system confidently.

## Positioning

A vibrant, professional design system for building distinctive productivity tools without starting from generic component-library defaults.

## Brand Personality

Vibrant, polished, distinctive.

The system combines Linear's compact precision with Raycast's tactile depth. Community themes such as Catppuccin and Dracula influence the color tokens without changing the system's underlying component language.

## Anti-references

Simple Base must not look like another generic shadcn component library. Avoid anonymous dashboard styling, interchangeable component-library defaults, and visual choices that erase the system's own identity.

## Design Principles

1. **Distinctive by default.** Components should have a recognizable Simple Base character before customization.
2. **Professional vibrancy.** Use color and depth confidently while preserving clarity, restraint, and credibility.
3. **Built for productive flow.** Components should feel compact, responsive, familiar, and efficient in task-focused applications.
4. **One system, many themes.** Themes may change color expression, but component behavior, hierarchy, and visual grammar remain cohesive.
5. **Fast to adopt, strong enough to keep.** Defaults should be polished enough for real products while tokens and components remain understandable and extensible.

## Accessibility & Inclusion

Target WCAG 2.2 AA across all supported themes. Components must support keyboard navigation, visible focus states, reduced-motion preferences, semantic markup, and sufficient text and control contrast. State and meaning must never rely on color alone.
